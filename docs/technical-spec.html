Doppel — a Swiss financial digital twin

Technical specification · UBS “AI Financial Twin” challenge · LauzHack 2026
Team TKT — Barlas Şen, Oktay Yüce, Meriç Şen · pitch slot 6, 13:20github.com/D0ktay/Doppel-TKT

What it is

From a person's profile and bank statement Doppel builds a twin of their finances and makes the future explorable: where the money goes today, where the current path leads, and what a decision changes. It does not predict; every result is conditional on stated assumptions.

Architecture

  • Web app: Next.js 15, React 19, TypeScript. The finance engine is deterministic TypeScript and runs in the browser.
  • One server route (/api/twin) is the only code that calls a language model; strict schemas, byte and token caps, rate limit and daily budget.
  • No database: accounts live in the browser's local storage. All data is fictional (UBS starter kit: 1'200 synthetic profiles, plus three built-in accounts).
  • Same app as a desktop app (Electron, server inside the app) and an Android shell (Expo). Optional hand control by camera (Python, MediaPipe) sends ordinary mouse and keyboard input.

Inputs, assumptions, outputs

InputsProfile (age, canton, income, balances, debt, goals); bank statement (CSV, camt.053, MT940, broker / 3a); scanned documents; decisions typed in EN / DE / FR / TR.
AssumptionsOne dated, sourced table: equities 6.5% ± 16%, bonds 2% ± 5%, inflation 1.2%, mortgage stress rate 5%, AHV / BVG / pillar 3a figures. Five economic scenarios change them: baseline, high inflation, recession, low rates, climate transition.
OutputsGoal odds, net-worth range (P10–P50–P90) over time, monthly budget before and after a decision, lowest cash point, mortgage affordability, retirement income.

Every parameter carries a provenance label: ubs_synthetic, derived, user or doppel_default.

Financial model

  • Seeded Monte Carlo: 1'000 monthly paths over asset classes (no single securities); the same seed gives the same result.
  • Swiss rules in code: affordability (5% imputed rate, 1% upkeep, one third of gross income; 20% equity, 10% of it hard), amortisation, AHV, BVG, pillar 3a, cantonal tax and health premiums.
  • Life decisions with sourced costs: child (phases, daycare, allowances, tax effect), car (cash, loan, lease, or GA instead), home, partner, move, education, workload, self-employment, job loss, windfall. A figure with no source is asked from the user, never assumed.
  • Behaviour twin: habits measured from transactions and trades (payday spending, subscriptions, selling in a drawdown) enter the simulation, so “you as you are” and “disciplined you” can be compared on the same markets.
  • Goal solver: finds the smallest change that reaches the goal.

Scenario and counterfactual exploration

  • Apply a decision and see its own cost lines, the budget before → after, net worth in 1, 5 and 10 years, and the odds before → after; the chart draws both lines.
  • Pin a Plan A and compare any other plan against it. Alexia's three starter-kit paths are built in.
  • /play: the same twin as a life game; a Monte Carlo tree search reviews each decision on the same simulated futures. A life choice is never graded as “best”.

Use of AI

  • The model never does arithmetic. It reads documents, parses free-form what-ifs the local parsers miss, and words answers.
  • Grounded answers: an answer containing a number the engine did not supply, or on the wrong time basis, is refused server-side.
  • Frugal cascade: QR decode → cache → local OCR and rules → small text model → small vision model; every call is in a token ledger the user can inspect.
  • Open-weight models (Qwen3 30B) through any OpenAI-compatible endpoint; the app works fully without a model.

Validation

Game49 checks, incl. bit-for-bit parity between the game simulator and the dashboard engine.
Gateway39 checks on guards, caps and refused answers, against a stubbed model.
UIHeadless browser run of the real pipeline at 320 px; four dictionaries checked for parity.
Hand control845 tests on recordings and synthetic input.

All reproducible from the repository with one command each, no key needed.

When a constraint is violated

  • Cash below zero is borrowed at 6% and counted as a cash crunch; its probability is shown.
  • A home that fails the bank test is not bought in that future; the card shows the gap and the highest price that passes.
  • A decision with missing inputs cannot be applied.

Limits

  • Synthetic data only; rates are stated assumptions, not forecasts; tax is an approximation.
  • Bank layouts follow typical exports and were not verified against real ones.
  • Not modelled: reference-rate rent rule, SARON path, old-age care.
  • With a live model about one answer in four is refused by the grounding check.
  • The mobile shell was not run on a phone; the Windows build was not run.
